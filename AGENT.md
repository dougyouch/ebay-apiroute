# AGENT.md

Guidance for AI coding agents (and people) working in this repository.

## What this repository is

`ebay-apiroute` publishes Python clients for eBay's APIs: 29 REST APIs (Buy, Sell, Commerce, Developer) and the SOAP Trading API. The clients are **generated** by [apiroute](https://github.com/dougyouch/apiroute) from the API specs eBay publishes. They're kept current by the weekly Build workflow, and released to PyPI as `ebay-apiroute`.

## Layout

| Path | What it is | Edit by hand? |
| --- | --- | --- |
| `apis.yaml` | Every API: spec URL, docs URL, module, client class, auth base class | **yes**: this is the source of truth |
| `specs/` | Committed copies of the specs, written by `scripts/generate.py --fetch` | no (fetch them) |
| `scripts/generate.py` | Fetches specs, runs `apiroute generate` per API, writes group `__init__`s, `trading_version.py`, the README table | yes |
| `src/ebay_apiroute/auth.py` | `EbayAuth` (REST OAuth, marketplace, sandbox) and `TradingAuth` (SOAP credentials, call name), which generated clients extend | **yes** |
| `src/ebay_apiroute/__init__.py` | Package docstring | yes |
| `src/ebay_apiroute/<group>/<api>/`, `trading/` | Generated clients (every file starts with `# Generated by apiroute`) | **never** |
| `src/ebay_apiroute/<group>/__init__.py`, `trading_version.py` | Written by `scripts/generate.py` | never |
| `tests/` | Config checks, REST auth, Trading SOAP | yes |
| `.github/workflows/` | `ci.yml`, `build.yml` (regenerate and commit), `release.yml` (every push to main: tag, PyPI, GitHub release) |
| `scripts/next_release.py` | Each release's version and notes, from the commits since the last tag | yes | yes |
| `.agent/skills/apiroute-client.md` | Skill for creating and maintaining repos like this one | yes |

## Rules

- **Never edit generated code.** CI regenerates from `specs/` and fails on any difference. To change generated output:
  - Edit `apis.yaml` or `auth.py` and regenerate.
  - If the generator itself is wrong, fix apiroute; the Build workflow picks up its next release.
- **Regenerate after any change** to `apis.yaml` or the generate script: `uv run python scripts/generate.py`. Add `--fetch` to download the latest specs first. Commit the specs and the generated code together.
- **Credentials belong in `auth.py`.** Every generated root client extends the `base_class` named in `apis.yaml`, and spec-declared security schemes aren't generated. REST APIs use `EbayAuth`; Trading uses `TradingAuth`.
- **Every merge to main is a release.** There's no release PR; `release.yml` tests, tags and publishes each push to main, Build's commits included.
- **Use conventional commits.** The version comes from the commits since the last tag:
  - `feat!:` (or a `BREAKING CHANGE:` footer) is a major release
  - `feat:` is a minor release
  - anything else (`fix:`, `docs:`, `chore:` ...) is a patch
- **The version lives in the git tag**, not `pyproject.toml` (hatch-vcs). Never tag by hand; the release workflow does.
- **Before committing:** `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest`.

## Common tasks

- **Add an eBay API:**
  1. Find its OpenAPI 3 contract: `https://developer.ebay.com/api-docs/master/<group>/<api>/openapi/3/<group>_<api>_<version>_oas3.json`.
  2. Check the download is JSON with an `openapi` key. eBay answers unknown URLs with a normal page instead of a 404.
  3. Add an entry to `apis.yaml`, using an existing one as a template.
  4. Run `scripts/generate.py --fetch --only <name>`, then the tests.
- **A spec change broke generation:** the Build workflow fails before committing anything. Reproduce with `scripts/generate.py --fetch --only <name>`, then fix apiroute or `auth.py`. Patching `specs/` by hand would be overwritten by the next fetch.
- **Remove an API:** delete its `apis.yaml` entry, its file in `specs/` and its folder under `src/ebay_apiroute/`, then regenerate.
- **Release:** nothing to do. Every push to main, and every Build commit, is tested, tagged `vX.Y.Z`, published to PyPI (trusted publishing, the `pypi` environment) and given a GitHub release with notes from its commits. Rerunning a failed Release finishes it.
